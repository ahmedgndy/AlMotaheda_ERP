# Report Management — design (brief Phase 4)

Date: 2026-10-16. Labels: **[Company]** from the brief · **[Industry]** recommendation · **[Confirm]** Needs Confirmation.

## 1. Shape

```
Reports module (schema rpt)            Owning modules (Finance, Projects, Workforce, Subcontractors, Fleet, HR)
  catalog + access check  ───────────►  IReportSource: the report's rows and totals, computed with the SAME
  run (JSON page, totals)               queries their screens and dashboards use (one calculation source)
  Excel export (.xlsx, ClosedXML)
  print page (HTML, RTL, A4)
  background exports + "ready" notification
  export / print history (audited)
```

- A report's **definition** (code, AR/EN name, who may run it, filters, columns, totals) lives next to its data in
  the module that owns the data, through `Reports.Contracts`. The Reports module never reads another module's
  tables [Company: modular monolith].
- **Full dataset**: export and print always run the report without paging (the filters only) [Company].
- **Drill-down**: each row may carry a link (`project`, `record`, `document`) the frontend opens; summary reports
  link to the detailed report with the filter set [Company].
- Engineers' Report Requests / Daily Project Report stay in Projects, untouched [Company].

## 2. Catalog (built now)

| Code | Report | Source | Who (permission) |
|---|---|---|---|
| `FIN-CASH` | Cash movement by day / week / month / custom range (money out, money in, net) | Finance ledger | finance F |
| `FIN-LEDGER` | Transaction ledger | Finance ledger | finance F |
| `FIN-REQUESTS` | Payment requests by status (pending, approved-unpaid, paid, failed…) | Finance | payments F |
| `FIN-RECON` | Reconciliation: every paid / reversed request against its ledger entries | Finance | finance F |
| `PRJ-COST` | Project cost summary by cost group (recognized, paid, outstanding, committed) | Projects | projects F, project in scope |
| `PRJ-ITEMS` | Project cost breakdown by item: suppliers vs internal labor vs subcontract | Projects | projects F, project in scope |
| `SUP-ACCOUNT` | Supplier account and payments | Projects | projects F |
| `WRK-PAYROLL` | Worker weekly payroll (approved days, gross, paid, outstanding per worker per week) | Workforce | workers F |
| `SUB-ACCOUNT` | Subcontractor account and payments | Subcontractors | subcontractors F |
| `EQP-COST` | Equipment cost by kind (rental, fuel, maintenance) per equipment and project | Fleet | equipment F |
| `EQP-FUEL` | Fuel by equipment and project (litres, cost) | Fleet | equipment F |
| `HR-SALARIES` | Employee salaries by month (salary sheet lines) | HR | hr F (HR, Accountant, Executive) |

Not built, data doesn't exist yet: office expenses vs budget, fuel **by driver** (no driver on fuel records),
money **in** (no income / client certificates module): shown as 0 with a note **[Confirm]**.

Managers see the project reports of their projects only (same project scope as everywhere). "Senior managers
(authorized Manager role)" = a Manager whose role or override grants the report's permission [Company].

## 3. Export and print

| | Rule | Label |
|---|---|---|
| Excel | `.xlsx` built on the server with ClosedXML (MIT): right-to-left sheet, header block (report, filters, generated by, generated at), typed cells (dates, money `#,##0.00`), totals row, frozen header | Company |
| Size | Up to 5,000 rows: the file is returned at once. Larger: a background export; the user is notified when it is ready and downloads it from the export history (kept 7 days) | Company / Industry |
| Print | A print-ready HTML page (A4, RTL for Arabic, header, totals) that the browser prints or saves as PDF | Industry — a server-side PDF library (e.g. QuestPDF) needs a commercial licence above US$1M revenue **[Confirm]** |
| Audit | Every export, download and print is stored (`rpt.ReportRun`: who, report, filters, rows, format, when) and so in the audit trail | Company |

## 4. Correctness

- Ledger reports read only `finance.LedgerEntry`; their totals are the ledger's [Company].
- Project, supplier, worker, subcontractor and equipment reports reuse the modules' own settlement rules
  (`ExpenseSettlement`, the worker FIFO, contract settlement, equipment cost queries), the same code their screens use.
- `FIN-RECON` flags any paid request whose ledger entries don't add up to its amount, and any ledger entry without
  a paid / reversed request [Industry].

## 5. Endpoints

`GET /api/reports` (the catalog the caller may run) · `GET /api/reports/{code}?…filters&page&pageSize` (rows,
totals) · `GET /api/reports/{code}/excel?…` (file, or 202 with an export id) · `GET /api/reports/{code}/print?…`
(HTML) · `GET /api/report-exports` (my exports) · `GET /api/report-exports/{id}/file`.
